# Задание 3. Вёрстка: исправить загрузку и отрисовку сайта

Результат работы: [отчёт](docs/REPORT.pdf) и [записи Performance](docs/performance/).

Задание к лекции [«Как работает браузер»](https://docs.google.com/presentation/d/1EIV2QLB37qf8hGHQNc2yglf67V6uUA67hmSw3RSEjUA/edit?usp=sharing).

**Дедлайн для получения полного балла — 25 ноября 2026 года включительно.**

Вам выдан готовый новостной сайт «Полоса» с 1000 карточками и локальным сервером. В клиентском коде намеренно допущены ошибки. Найдите и исправьте их, сохранив содержимое, оформление и функции сайта.

## Запуск

Нужен Node.js 20 или новее. Внешних зависимостей нет, `npm install` не требуется.

```sh
git clone https://github.com/itmo26-27/html-task-3.git
cd html-task-3
npm start
```

Откройте **http://127.0.0.1:4173/?scenario=normal**. Сервер останавливается сочетанием `Ctrl+C`. Если порт занят, выберите другой: `PORT=4174 npm start` в macOS/Linux или `$env:PORT=4174; npm start` в PowerShell.

Страницу нужно открывать через сервер, а не как локальный HTML-файл. После изменения файлов достаточно перезагрузить страницу. Для новой версии CSS и JS используйте перезагрузку с отключённым кешем.

## Что нужно сделать

1. **Исправить начальную загрузку.** В режиме `slow` заголовок и вводный текст должны быть видны до завершения загрузки иллюстрации и скрипта статистики. Пустой экран до окончания всех запросов не считается исправлением.
2. **Устранить скачки страницы.** Поздняя загрузка иллюстрации и шрифта не должна сдвигать заголовок, вводный текст, панель выбора вида и первую карточку. Сравнивайте положение этих блоков после первого появления текста и после завершения загрузки.
3. **Исправить нестабильную работу скриптов.** В каждом из четырёх режимов кнопки «Подробно» и «Компактно» работают без ошибок в консоли. Инициализация выполняется ровно один раз, один клик вызывает одно переключение.
4. **Исправить структуру описаний.** В каждой карточке полный текст описания, включая начало, середину и последнюю фразу, находится внутри её `.story-summary`. В подробном виде описание видно целиком, в компактном — скрыто целиком. Заголовок, дата, время чтения и ссылка остаются видимыми и принадлежат своей карточке.
5. **Ускорить переключение вида.** Все 1000 карточек остаются в DOM. При переходе из подробного вида в компактный медианное суммарное время событий Layout должно уменьшиться минимум вдвое относительно исходной версии. Сохраняются порядок карточек, их тексты и конечное оформление обоих видов.

Ожидаемый результат после завершения загрузки показан на [контрольных изображениях](docs/EXPECTED.md). Это ориентир структуры и оформления; различия сглаживания текста между ОС допустимы.

## Контрольные режимы

| Адрес | Условия |
| --- | --- |
| [normal](http://127.0.0.1:4173/?scenario=normal) | Обычная загрузка, исходная точка для измерения Layout |
| [slow](http://127.0.0.1:4173/?scenario=slow) | Долгие запросы статистики, иллюстрации и шрифта |
| [race](http://127.0.0.1:4173/?scenario=race) | Библиотека инструментов загружается позже приложения |
| [reverse](http://127.0.0.1:4173/?scenario=reverse) | Другой порядок завершения запросов |

Задержки воспроизводимы и задаются сервером. Подробные шаги и правила замеров — в [сценариях проверки](docs/CHECKS.md).

## Границы работы

- Изменяйте HTML, CSS и JavaScript в `public/`. `public/card.html` — шаблон, из которого сервер собирает 1000 карточек. Это тоже часть вашего решения.
- Сохраните идентификаторы элементов управления, `#news-feed`, `.news-card`, `.story-summary`, `data-news-id`, `data-init-count` и отметку `news:view-change`: они нужны для сопоставимых проверок. Можно менять окружающую разметку и способ реализации.
- Не меняйте `server.mjs`, `fixture/`, данные новостей и настройки задержек. Сохраняйте передачу `scenario` в запросах ресурсов. `{{scenario}}` в HTML и CSS подставляется сервером.
- Не удаляйте ресурсы, не подменяйте шрифт системным, не сокращайте число карточек и не используйте виртуализацию, `content-visibility`, снимок страницы или отключение функций для прохождения замеров.
- Статистика должна загружаться и регистрировать просмотр страницы. Изображение и локальный шрифт должны оставаться частью сайта. Не подменяйте ожидание ресурсов заранее подобранными таймерами.
- Не стирайте ошибки из консоли и не меняйте диагностический счётчик вместо исправления повторной инициализации.

Команда `npm test` проверяет только сервер, данные и доступность ресурсов. Её успешный результат **не означает**, что клиентские ошибки исправлены.

## Что сдать

- Репозиторий с исправленным проектом. Исходная версия доступна по тегу `starter`.
- Отчёт по пяти пунктам: что было сломано, причина, изменение и подтверждение результата.
- Снимки Network и Elements, запись Performance с переключением вида, подтверждение раннего появления текста и отсутствия скачков.
- Таблицу пяти замеров до и после с медианами. Укажите браузер, размер окна, настройки CPU/сети и состояние кеша. Большие записи можно приложить ссылкой.

## Оценивание

Максимум — **10 баллов**: **5 за исправления + 5 за объяснение и доказательства**.

Каждый из пяти пунктов даёт один балл за корректное поведение и один балл за объяснение причины, связанное с кодом и наблюдениями в браузере.
