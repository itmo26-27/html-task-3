# Отчёт по заданию 3

## Условия проверки

- Google Chrome 157.0.8103.79, Windows, область страницы 1280 × 1000 CSS-пикселей, масштаб 100%.
- CPU и Network: No throttling. Для холодной загрузки включён Disable cache.
- Проверены `normal`, `slow`, `race` и `reverse`, а также повторная загрузка с прогретым кешем.

Во всех режимах на странице остаются 1000 карточек, `data-init-count="1"`, один клик создаёт одну запись `news:view-change`, статистика загружается, ошибок в Console нет.

## 1. Начальная загрузка

**Проблема.** `analytics.js` в `<head>` блокировал разбор HTML. В режиме `slow` страница ждала его восемь секунд.

**Исправление.** Для скрипта добавлен `async`. Статистика продолжает загружаться, но больше не мешает показу страницы.

**Результат.** Текст виден, пока статистика, изображение и шрифт ещё загружаются: [ранний кадр](screenshots/network-slow-pending.png). После загрузки все семь запросов имеют статус 200: [готовая загрузка](screenshots/network-slow-complete.png).

## 2. Скачки страницы

**Проблема.** Для SVG не были указаны размеры, а высота строк заголовка зависела от загружаемого шрифта. Из-за этого блоки могли сдвигаться.

**Исправление.** Изображению заданы размеры `1200 × 360`, заголовку — `line-height: 1.1`.

**Результат.** Место под изображение известно заранее, а Performance показывает `CLS = 0.00`: [скриншот](screenshots/performance-cls-zero.png).

## 3. Работа скриптов

**Проблема.** `tools.js` и `app.js` загружались через `async`, поэтому порядок их выполнения не был гарантирован. Кроме того, `init` запускался два раза и добавлял повторные обработчики.

**Исправление.** Скрипты подключены через `defer` в нужном порядке. Инициализация выполняется один раз и проверяет `data-init-count`.

**Результат.** Ошибок в Console нет: [скриншот](screenshots/console-no-errors.png). Кнопки правильно включают [подробный](screenshots/view-detailed.png) и [компактный](screenshots/view-compact.png) виды.

## 4. Структура описаний

**Проблема.** Внутри `<p>` находился `<div>`. Браузер закрывал абзац раньше времени, поэтому часть описания оказывалась вне `.story-summary`.

**Исправление.** `.summary-details` заменён на `<span>`. Теперь все три части описания находятся внутри одного `.story-summary`.

**Результат.** Правильная структура видна в Elements: [скриншот](screenshots/elements-story-summary.png). В компактном виде описание скрывается целиком, остальные данные карточки остаются видимыми.

## 5. Скорость переключения

**Проблема.** Старый обработчик изменял каждую из 1000 карточек и сразу читал её размеры. Это вызывало много повторных Layout.

**Исправление.** JavaScript теперь меняет только `data-view` у `#news-feed`, а внешний вид карточек переключается через CSS. Все 1000 карточек остаются в DOM.

**Результат.** Пример Bottom-up для исправленной версии: [скриншот](screenshots/performance-layout-bottom-up.png).

Для сравнения сделано по пять записей исходной и исправленной версий в `scenario=normal`. В каждом прогоне страница загружалась заново, Screenshots были отключены, измерялся один переход «Подробно → Компактно». Записи сохранены в `performance-traces/`.
