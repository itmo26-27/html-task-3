# Отчёт

## 1. Начальная загрузка

**Было:** статистика загружалась синхронным скриптом в `<head>` и задерживала разбор HTML. Иллюстрация не имела заданных размеров, поэтому её загрузка могла сдвигать содержимое.

**Сделано:** `analytics.js` загружается с `async`, `tools.js` и `app.js` — с `defer` в порядке документа. Иллюстрации заданы исходные размеры 1200 × 360.

**Проверено:** в сценарии `slow` текст уже отображался, пока `campus.svg` и `analytics.js` ещё загружались. В браузере запрос иллюстрации занял 3 804 мс, запрос статистики — 8 003 мс. В `reverse` иллюстрация загрузилась за 303 мс, а шрифт — за 2 005 мс. В `normal`, `slow`, `race` и `reverse` все семь ресурсов получили HTTP 200. В каждом сценарии обе кнопки отрабатывали, `initCount` оставался равен 1, один клик добавлял ровно одно измерение `news:view-change`, число карточек оставалось 1000; Console errors — 0. В `slow` запросы иллюстрации и статистики завершились через 3 804 и 8 003 мс.

Снимки DevTools: [Elements](evidence/elements-panel-clean.jpeg) показывает компактное состояние ленты, значение `data-init-count="1"` и три части описания внутри `.story-summary`. [Network](evidence/network-panel-clean.jpeg) показывает семь загруженных ресурсов со статусом 200.

Снимки первого отображения и после загрузки: [slow до](evidence/slow-first-frame.jpeg), [slow после](evidence/slow-after-load.jpeg), [reverse до](evidence/reverse-first-frame.jpeg), [reverse после](evidence/reverse-after-load.jpeg). Полные измерения прямоугольников и загрузок находятся в [browser-results.json](evidence/browser-results.json).

## 2. Скачки страницы

**Было:** высота заголовка зависела от метрик резервного шрифта, а место под иллюстрацию до её загрузки не резервировалось.

**Сделано:** заголовку задан `line-height: 1.3` и резервный Georgia; изображению заданы intrinsic dimensions.

**Проверено:** в `slow` размеры и координаты `#lead-title`, `.lead-intro`, `.archive-toolbar` и первой `.news-card` совпали до загрузки иллюстрации/статистики и после загрузки всех ресурсов. В `reverse` те же прямоугольники совпали, когда иллюстрация уже загрузилась, а шрифт ещё нет, и после загрузки шрифта. Максимальная измеренная разница по `x`, `y`, ширине и высоте — **0 CSS px** при viewport 1280 × 1000 CSS px и DPR 1.

## 3. Работа скриптов

**Было:** `init` вызывался при `DOMContentLoaded` и повторно при `load`. Скрипты с `async` могли выполниться в неправильном порядке.

**Сделано:** `defer` сохраняет порядок `tools.js` → `app.js`; приложение запускает `init` один раз после разбора HTML. Переключатель меняет общий атрибут `data-view`, без измерения и переназначения стилей каждой карточки в цикле.

**Проверено в Chrome:** исходная версия показывала `data-init-count = 2`; исправленная — `1`. В каждом из пяти повторов один клик давал один новый `news:view-change`, переключал вид на `compact`, а число карточек оставалось 1000. Обратный клик возвращал `detailed`, не повторяя инициализацию. Console errors — 0.

## 4. Структура описаний

**Было:** `<div class="summary-details">` находился внутри `<p>`, что некорректно и браузер выносил его из описания.

**Сделано:** все три части (`.summary-lead`, `.summary-details`, `.summary-ending`) — `span` внутри одного `.story-summary`. В компактном виде CSS скрывает весь контейнер; в подробном он отображается.

**Проверено для 1000 карточек:** в исходной версии все три части не были вложены в `.story-summary` (`nested: false`); в исправленной — вложены во всех карточках (`nested: true`). У первой карточки `display: block` в подробном виде и `display: none` в компактном. Количество карточек во время переключений не менялось.

## 5. Переключение вида и Layout

**Было:** обработчик проходил по 1000 карточкам, менял каждой класс и inline-стили, затем вызывал `getBoundingClientRect()`. Это приводило к повторным пересчётам Layout.

**Сделано:** компактный вид задаётся CSS-селекторами по `#news-feed[data-view="compact"]`; JavaScript обновляет состояние ленты, aria-состояния кнопок, подпись и метку измерения.

Проведено по пять записей на версию в изолированном Chrome без расширений и фоновых вкладок: Chrome Headless 158.0.8127.88, macOS, viewport 1280 × 1000 CSS px, DPR 1, CPU без ограничения, Network без ограничения, cache disabled. На каждом повторе страница загружалась заново, дожидались `load` и `document.fonts.ready`; фиксировался клик по кнопке «Компактно» и следующий кадр. Layout self-time посчитано по `tdur` событий `Layout` в trace. Все десять исходных трассировок сохранены в `evidence/`.

| Прогон | Исходная версия, Layout self-time, мс | Исправленная версия, Layout self-time, мс |
| --- | ---: | ---: |
| 1 | 1233,071 | 12,648 |
| 2 | 860,242 | 12,912 |
| 3 | 1054,228 | 13,365 |
| 4 | 838,429 | 13,899 |
| 5 | 1124,191 | 13,636 |
| **Медиана** | **1054,228** | **13,365** |

Медиана исправленной версии составляет **1,27%** от исходной, то есть Layout self-time снизился примерно в **78,9 раза**. Условие «не более половины исходной медианы» выполнено. В исходных записях было 2002 события `Layout` на переключение, в исправленных — 1.

## Изменённые файлы

- `public/index.html` — порядок и режим загрузки скриптов, размеры изображения.
- `public/card.html` — корректная вложенность частей описания.
- `public/css/site.css` — стабильные метрики заголовка и единое CSS-переключение компактного вида.
- `public/js/app.js` — единственный запуск `init` и один обработчик на кнопку без принудительного Layout по каждой карточке.
- `docs/REPORT.md` и `docs/evidence/` — объяснение изменений и результаты браузерной проверки.
